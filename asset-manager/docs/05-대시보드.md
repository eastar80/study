# 대시보드 (4단계)

원본 분석(`01` §3)의 대시보드는 서브탭 6개였다. 그중 **자산 현황 · 자산 및 부채 구성 · 추이**를
만들었다. 나머지는 만들지 않았고, 이유가 각각 다르다.

| 원본 서브탭 | 상태 | 이유 |
|---|---|---|
| 자산 현황 (KPI 4개) | ✅ | |
| 자산 및 부채 구성 | ✅ | |
| 12개월 추이 | ✅ | 원본에 없지만 대장 데이터로 가장 값이 큰 화면 |
| 부채 상세 분석 (이자·상환율) | ❌ | 금리 소스가 없다 (`03` §2.6) |
| 포트폴리오 현황 | ⏸ | 5단계. 시세 프록시가 필요하다 |
| 수입·지출 현황 | ❌ | 가계부를 구현하지 않는다 |
| 목표 금액 계산기 | ⏸ | 독립 기능이라 나중에 붙여도 된다 |
| 통화별 자산 | ⏸ | 파일 1에 외화가 없다. 데이터가 생기는 5단계에 함께 만든다 |

**대시보드는 자기 데이터를 저장하지 않는다.** 모든 숫자를 `snapshots` 에서 집계하므로 대장과
어긋날 수 없다. 부호도 `ledger.ts` 의 `displayAmount` 를 그대로 쓴다.

---

## 1. 부호가 만든 설계 문제 — 음수 부채는 막대에 넣을 수 없다

마통이 자산 상태인 달(`03` §2.4)에는 부채 분류의 합계가 **음수**가 된다. 누적 막대에서 음수 조각은
너비를 정할 방법이 없다.

**음수 분류는 막대에서 빼고 차감 항목으로 따로 적는다.** 구성 막대는 "부채가 무엇으로 이루어져
있는가"를 답하는 그림이고, 계좌에 든 돈은 부채의 **구성 요소가 아니라 상계**다. 그래서
`summariseMonth` 가 `debts` 와 `debtOffsets` 를 나눠서 돌려주고, 화면은 막대 아래에 "빚이 아니라 돈을
들고 있었다"고 적는다. `debt` 합계 자체는 상계를 반영한 값이라 KPI와 순자산은 그대로 맞는다.

## 1.5 합계에서 제외되는 항목

`Item.countedElsewhere`(`03` §2.4)가 붙은 항목은 **어떤 합계에도 더하지 않는다.** 마통이 그 경우로,
`은행부채` 가 이미 포함하고 있어 더하면 두 번 세게 된다.

`summariseMonth` 는 이런 항목을 `excluded` 로 따로 돌려주고 화면이 부채 카드에 사유와 함께 적는다.
**조용히 빼면 합계가 위의 행들과 어긋나는 이유를 아무도 알 수 없다.** 대장 행에는 `합계 제외` 배지가
붙는다.

`dashboard.ts` 의 분기를 `ASSET | DEBT | EXCLUDED` 세 갈래로 쓴 이유가 여기 있다. "부채가 아니면
자산"으로 쓰면 제외 대상이 **조용히 자산으로 새고**, 그게 이 버그가 오래 보이지 않은 방식이다.

## 2. 전월 대비는 "이전에 기록이 있는 달" 대비다

`changeAgainstPrevious` 는 직전 **달**이 아니라 직전 **기록**과 비교하고, 비교한 달을 함께 반환한다.
화면이 `2026-06 대비` 라고 그 달을 직접 적는 이유다. 구멍이 있는데 "전월 대비"라고 쓰면 거짓말이 된다.

레버리지 비율의 변화는 퍼센트가 아니라 **퍼센트 포인트(%p)** 이고 소수 두 자리로 적는다. 한 자리로는
작은 변화가 `−0%` 로 무너져 아무 정보가 없다.

## 3. 차트 규칙

### 3.1 팔레트는 검증된 순서다 — 색을 고르지 말고 계산한다

색상값은 `index.css` 의 `--series-1` ~ `--series-8` 에 있다. TS가 아니라 CSS에 둔 이유는 다크 모드
전환에 JavaScript가 개입하지 않게 하는 것이다.

**슬롯 순서가 색약 안전장치다.** 인접 쌍이 이 앱의 카드 배경(`#ffffff` / `#1c1f27`)에서 CVD ΔE 8,
정상 시야 ΔE 15를 넘는 것을 검증기로 확인한 순서다. 따라오는 제약이 세 개 있다.

1. **순서대로 배정하고 아홉 번째를 만들지 않는다.** 생성한 색은 기존 슬롯과 구별되지 않는다.
   아홉 번째는 `기타` 로 접는다.
2. **누적 막대는 슬롯 순서로 그린다.** 금액 순으로 그리면 인접 쌍이 검증 대상이 아닌 조합이 되고,
   실제로 노랑이 주황 옆에 붙었다 — 문서가 유일하게 실패한다고 지목한 쌍이다. 범례만 금액 순으로
   정렬한다. 막대가 달마다 재배열되지 않는 부수 효과도 얻는다.
3. **자산과 부채는 슬롯 순서를 따로 쓴다.** 하나로 이으면 부채 분류가 여덟 번째를 넘겨 주 부채
   막대가 회색(`기타`)이 된다. 둘은 범례가 각각 있는 별개의 차트다.

밝은 모드의 세 색은 흰 배경에서 대비 3:1 아래다. 그래서 **모든 차트가 이름과 금액을 담은 범례를
같이 낸다.** 색만으로 값을 읽게 하지 않는다.

값을 바꿀 때는 눈으로 판단하지 말고 검증기를 다시 돌린다:

```
node scripts/validate_palette.js "<hex,...>" --mode light --surface "#ffffff"
node scripts/validate_palette.js "<hex,...>" --mode dark  --surface "#1c1f27"
```

### 3.2 추이 차트

- **축은 하나다.** 자산·부채·순자산이 모두 원이라 같은 축에 놓인다. 축을 두 개 쓰면 두 축의 정렬이
  임의여서 데이터에 없는 상관관계를 만들어낸다.
- 0 기준선을 포함한다(`niceTicks` 기본값). 부채는 0 근처에 있고 부호를 넘나들 수 있어서, 기준선이
  떠 있으면 변화의 크기를 잘못 읽는다. 0에서 먼 계열만 그릴 때는 `includeZero: false` 로 끈다.
- 선 2px, 끝점 반지름 4px에 배경색 2px 링(선이 교차하는 자리에서 살아남게), 격자선은 실선 1px.
  점선 격자는 임계선처럼 읽힌다.
- 계열이 3개라 **범례를 항상 두고** 끝점에 직접 라벨을 붙인다. 모든 점에 숫자를 적지는 않는다.
- **호버는 기본 기능이다.** 라벨이 붙은 양 끝 사이의 값을 읽을 방법이 없으면 독자가 추측하게 된다.
  다만 호버가 유일한 경로여서는 안 되므로 `표로 보기` 를 같이 둔다.
- `자산보유현황` X열 이벤트 메모를 축 아래 짧은 눈금으로 표시하고 호버 시 본문을 보여준다. 원본
  시트가 그 메모를 변곡점 설명으로 쓰던 용도(`03` §3.2) 그대로다.
