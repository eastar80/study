# 기존 시트 → 앱 데이터 매핑

임포터의 사양서. 컬럼 단위 매핑은 구조 보고서를 받은 뒤 채운다.
현재는 **대상 범위와 설계 규칙**까지 확정되어 있다.

---

## 1. 대상 시트

두 개의 Google 스프레드시트에서 **6개 시트**만 사용한다. 나머지는 읽지 않는다.

### 파일 1 — 자산현황 (`자산현황_ver7.3_20220331`)

| 시트 | 역할 | 임포트 |
|---|---|---|
| **잔액입력** | 현재 자산 입력 | ✅ 자산 |
| **자산보유현황** | **L 컬럼 이후가 부채 입력** | ✅ 부채 (L열 이후만) |

### 파일 2 — 자산운용수익률

| 시트 | 역할 | 임포트 |
|---|---|---|
| **입력정보** | 현재 증권 내역 입력 | ✅ 보유 종목 |
| **기준가(월)** | 월별 내역 기록 | ✅ 월별 성과 |
| **기준가(연)** | 연별 내역 기록 | ✅ 연별 성과 |
| **포트폴리오_전체** | 조회용 모니터링 화면 | ❌ 화면 설계 참고만 |

---

## 2. 확정된 설계 규칙

### 2.1 `자산보유현황` 은 조회 시트가 아니다

한 시트 안에 **조회 영역과 입력 영역이 공존한다.** L 컬럼 이후가 부채 입력이며,
**부채 데이터의 유일한 출처**다.

따라서 임포터는 **시트 단위가 아니라 열 범위 단위로** 대상을 잡는다.
`자산보유현황` 을 "조회 시트니까 건너뛴다"고 판단했다면 부채가 통째로 빈 앱이 나왔을 것이다.

| 영역 | 처리 |
|---|---|
| A ~ K (추정) | 집계·조회 → 임포트하지 않음. 우리 대시보드로 재현 |
| L 이후 | 부채 입력 → `items(isLoan: true)` + `snapshots(amount, rate)` |

L 열이 정확한 경계인지는 구조 보고서의 컬럼 프로파일로 확인한다.

### 2.2 파생된 값은 임포트하지 않는다

조회·집계 시트를 임포트하면 계산 결과를 사실로 굳혀버린다. 원본이 바뀌어도 따라가지 못하고,
우리 앱의 집계 로직과 이중으로 존재하게 된다. **입력 시트만 가져오고, 조회 화면은 우리 쪽에서
다시 계산한다.**

`포트폴리오_전체` 를 임포트 대상에서 뺀 이유가 이것이다. 대신 그 화면 구성은 우리 포트폴리오
화면을 설계할 때 참고한다.

### 2.3 두 파일에 중복된 자산 — 정본은 파일 2

사용자 확인: 파일 1 `잔액입력` 의 자산 중 **일부는 파일 2의 증권 정보**이며, **값이 조금 어긋날 수
있다.**

| 규칙 | 내용 |
|---|---|
| 정본 | **투자자산은 파일 2 `입력정보`**. 종목·수량·단가가 거기서 관리되므로 파일 1의 해당 항목은 파생값이다 |
| 표시 | 파일 1의 증권 관련 항목은 임포트하되 **"파일 2와 중복" 표시**를 단다 |
| 충돌 | 두 값의 차이를 **임포트 미리보기에 나란히 보여주고 사용자가 고르게** 한다 |

**조용히 한쪽을 이기게 하지 않는다.** 자산 총액이 말없이 틀어지는 것이 이 앱에서 가장 나쁜
실패다. 자동 병합 규칙을 넣는 대신 차이를 드러내고 사람이 판단하게 한다.

### 2.4 `기준가(월)` / `기준가(연)` 은 스키마에 대응 엔티티가 없다

`docs/02-구현-방침.md` 의 데이터 모델에는 월별·연별 **성과(수익률) 기록**에 해당하는 엔티티가
없다. 지금 모델은 자산 잔액 스냅샷 중심이다.

구조 보고서를 보고 판단할 것:

- 기준가가 **포트폴리오 전체의 단위가격**(펀드처럼 좌당 기준가) 방식인가
- 그렇다면 `snapshots` 로 환원 가능한가, 아니면 별도 엔티티(`navHistory` 등)가 필요한가
- 연별 시트가 월별의 집계라면 **연별은 임포트하지 않고 월별에서 계산**한다 (2.2 규칙 적용)

---

## 3. 컬럼 매핑

*구조 보고서 수신 후 작성.*

확정할 항목:

| 원본 | → | 대상 |
|---|---|---|
| `잔액입력` | → | `categories` / `items` / `snapshots` (자산) |
| `자산보유현황` L열 이후 | → | `items(isLoan)` / `snapshots(amount, rate)` (부채) |
| `입력정보` | → | 종목 · 수량 · 평균단가 (5단계 포트폴리오) |
| `기준가(월)` | → | 미정 (2.4 참조) |
| `기준가(연)` | → | 미정 (2.4 참조) |

각 시트에서 확인이 필요한 것:

1. 월 축이 가로(열)인가 세로(행)인가, 기간은 어디부터 어디까지인가
2. 상위/하위 분류를 병합셀·배경색·들여쓰기·별도 컬럼 중 무엇으로 표현하는가
3. 외화 항목을 원통화로 적는가 원화 환산으로 적는가, 환율 컬럼이 있는가
4. 대출 금리를 어느 위치에 적는가
5. 합계 행·열이 어디인가 (임포트 대상이 아니라 검증 대조용으로 쓴다)
