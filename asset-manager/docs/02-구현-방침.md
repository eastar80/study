# 구현 방침 — 원본과 같게 갈 것 / 다르게 갈 것

전제: 이 앱은 **본인 한 사람이 쓰는 개인용**이다. 원본은 여러 사용자에게 서비스하는 형태라
회원 등급·고객센터·관리자 설정 같은 운영 기능이 붙어 있지만, 우리는 그게 필요 없다.
이 차이 하나가 아키텍처 전체를 바꾼다.

---

## 1. 확정된 결정

| 항목 | 결정 |
|---|---|
| 데이터 보관 | **사용자 본인의 Google Drive** (서버 없음) |
| 기존 시트 | 구조를 스키마의 원본으로 삼고, **과거 데이터 전량 임포트** |
| 1차 범위 | **자산 대장 + 대시보드** |
| 시세 | **자동 연동** (Yahoo Finance + Cloudflare Workers 프록시) |
| 화면 우선순위 | **데스크톱 우선**, 태블릿도 정식 지원 |
| 제외 | **가계부 모듈 전체**, **관리자 설정**, 고객센터, 회원 등급 |

## 2. 아키텍처

```
   ┌──────────────────────────────────────────┐
   │  브라우저 (데스크톱 / 태블릿)              │
   │  ┌────────────────────────────────────┐  │
   │  │  React SPA (정적 파일)              │  │
   │  │  - 화면 렌더링, 모든 계산 로직        │  │
   │  │  - IndexedDB 로컬 캐시 (오프라인)     │  │
   │  └──────┬──────────────────┬──────────┘  │
   └─────────┼──────────────────┼─────────────┘
             │                  │
   ┌─────────▼────────┐  ┌──────▼──────────────────┐
   │ GitHub Pages     │  │ 내 Google Drive          │
   │ (앱 파일만 배포)  │  │ /Asset Manager/data.json │
   │ 무료             │  │ ← 금융 데이터는 여기에만   │
   └──────────────────┘  └─────────────────────────┘
                                    │
                         ┌──────────▼───────────────┐
                         │ Cloudflare Workers (4단계)│
                         │ 시세·환율 중계 + 캐시. 무료 │
                         │ 개인정보 통과 안 함        │
                         └──────────────────────────┘
```

**핵심**: 금융 데이터가 지나가는 서버가 하나도 없다.
GitHub Pages는 앱 코드(HTML/JS)만 내려주고, 데이터는 브라우저 ↔ 본인 Drive 사이에서만 오간다.
시세 프록시는 "TSLA 주가 얼마?"만 물어보므로 보유 수량·금액을 알지 못한다.

### 기술 선택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | React + TypeScript + Vite | 금액 계산이 많아 타입 안정성이 필요 |
| 스타일 | Tailwind CSS | 원본과 유사한 카드형 UI를 빠르게 |
| 표 | TanStack Table | 대장 그리드의 sticky 컬럼·가상 스크롤 |
| 차트 | ECharts | 트리맵·이중축 복합차트를 모두 지원 |
| 인증 | Google Identity Services | 팝업 토큰 방식, 백엔드 불필요 |
| 저장 | Google Drive API v3 | 파일 1개 읽기/쓰기 |
| 배포 | GitHub Pages | 무료, 이 저장소에 이미 설정 경험 있음 |

### 권한 범위 (scope)

**`drive.file` 하나만 요청한다.** 이 범위는 "이 앱이 만들었거나 사용자가 직접 고른 파일"에만
접근할 수 있다. Drive의 다른 문서·사진은 앱이 볼 수 없다. Gmail·연락처는 당연히 접근 불가.

즉 처음에 걱정하셨던 "구글 계정으로 시작하기"를 이번엔 **본인이 만든 앱에서, 본인이 발급한
OAuth 클라이언트로, 최소 권한만** 눌러 쓰게 된다. 동의 화면에 "이 앱은 Google에서 확인되지
않았습니다"가 뜨는데, 본인이 만든 앱이니 정상이다.

### 저장 파일 형태

```
/Asset Manager/            ← Drive에 눈에 보이는 폴더로 생성
  data.json                ← 전체 데이터 (Drive가 버전 이력 자동 보관)
  backup/2026-08.json      ← 월 1회 자동 스냅샷
```

- 저장은 편집 후 디바운스(2~3초) → 자동 저장, 토스트 표시
- 저장 전 Drive의 `revisionId`를 비교해 다른 기기의 변경을 덮어쓰지 않도록 방어
  (데스크톱과 태블릿을 오가며 쓰므로 이 방어가 실제로 필요하다)
- 앱이 사라져도 `data.json`은 Drive에 그대로 남는다. 사람이 읽을 수 있는 JSON이다.

## 3. 원본과 **다르게** 갈 부분

### 3.1 제외할 것
- **가계부 모듈 전체** — 수입/지출/이체 기록, 예산, 지출 분석, 결제수단
- **관리자 설정**, 고객센터, 회원 등급 배지(PLATINUM), 베타 테스터 관리

가계부를 빼면 대시보드도 따라 줄어든다. 원본의 대시보드 탭 6개 중 **수입/지출 섹션이 빠져
5개**가 된다: `자산 현황 · 자산 구성 · 부채 분석 · 포트폴리오 · 계산기`.
저축률 KPI도 사라진다(가계부 수입/지출이 있어야 계산되는 값이다).
계산기의 "월 적립금"은 사용자가 직접 입력하는 값이므로 그대로 남는다.

### 3.2 대시보드 탭을 진짜 라우트로
원본은 대시보드 탭이 **한 페이지 스크롤 앵커**로 보인다. 각 탭을 실제 라우트
(`#/dashboard/debt` 등)로 분리해 딥링크와 뒤로가기가 자연스럽게 동작하게 한다.

### 3.3 비교 기준 통일
원본은 대시보드 KPI가 **전월 대비**, 자산관리 홈 KPI가 **전년 대비**로 갈려 있다.
같은 카드인데 기준이 다르면 헷갈린다. 카드 상단에 `[전월] [전년]` 토글 하나를 두고
사용자가 고르게 한다.

### 3.4 통화 — 집계는 원화, **표시는 원통화**

요구사항이 갈린다.
- **순자산·총자산·구성비·추이 차트** → 통화가 섞여 있으므로 **원화 환산**이 유일한 공통 분모
- **개별 자산을 눈으로 볼 때** → 달러 자산은 `$`, 엔 자산은 `¥`로 보여야 읽힌다
  ("$12,340"이 "₩17,092,000"보다 그 계좌의 실제 감각에 가깝다)

그래서 **저장은 원통화, 집계는 환산, 표시는 문맥에 따라** 세 층으로 나눈다.

**저장**
- `items[].currency` — 항목 단위로 통화를 지정 (`KRW` 기본, `USD`, `JPY` …)
- `snapshots[].amount` — **환산하지 않은 원통화 금액 그대로** 저장
- `fxRates[ym]` — **월말 환율 스냅샷**. 한 번 확정되면 고정

원통화로 저장하는 이유: 오늘 환율이 움직여도 "작년 12월에 내가 $10,000 갖고 있었다"는
사실은 변하지 않는다. 환산액을 저장하면 이 사실이 뭉개진다.

월말 환율을 고정하는 이유: 그래야 과거 순자산 추이 그래프가 흔들리지 않는다.
오늘 환율로 전 구간을 환산하면 어제 본 작년 순자산과 오늘 본 작년 순자산이 달라진다.

**표시 규칙**

| 위치 | 표시 |
|---|---|
| 대장 셀 (개별 항목) | **원통화** — `$12,340.00` / `¥250,000` / `₩12,000,000` |
| 항목 행 라벨 | 통화 배지 (KRW 항목은 배지 생략) |
| 그룹 소계 — 그룹 내 통화가 **하나**면 | 그 통화로 표시 + 원화 환산 작게 병기 |
| 그룹 소계 — 통화가 **섞였으면** | 원화만 |
| 총자산·순자산·총부채 KPI | 원화 |
| 구성비 스택바, 추이 차트 | 원화 |
| 부채 상세 (대출별) | 해당 대출의 원통화 |

**추가 화면 (원본에 없음)**
대시보드 자산 구성 탭에 **통화별 자산 현황** 카드를 넣는다.

```
  ₩ 원화 자산    ₩ 412,300,000   (61.0%)
  $ 달러 자산    $     168,420   ≈ ₩ 233,262,000   (34.5%)
  ¥ 엔화 자산    ¥   4,200,000   ≈ ₩  30,450,000   ( 4.5%)
```

환율 변동이 순자산에 얼마나 영향을 주는지 한눈에 보이게 하는 카드다.
원본에는 없지만 외화 자산 비중이 있으면 반드시 필요한 뷰다.

**환율 입력**
- 4단계(시세 프록시) 이후: 월말 환율 자동 수집 (`KRW=X`, `JPYKRW=X`)
- 그 전까지: `환경 설정 > 환율` 에서 월별 수동 입력 표
- 임포트 시 기존 시트에 환율 컬럼이 있으면 그대로 가져온다
- 특정 월 환율이 비어 있으면 그 월은 **"환산 불가"로 명시 표시**한다. 임의로 최근 환율을
  끌어다 쓰지 않는다 — 조용히 틀린 숫자를 보여주는 것보다 낫다

### 3.5 데스크톱 우선, 태블릿 정식 지원
주 사용 환경이 데스크톱이므로 데스크톱 레이아웃을 기준으로 설계하고, 태블릿은 축소가 아니라
별도 대응을 한다.

| | 데스크톱 (≥1280px) | 태블릿 (768~1279px) |
|---|---|---|
| 대장 그리드 | 12개월 전부 표시 | 항목 컬럼 sticky + 월 가로 스크롤 |
| 사이드바 | 항상 펼침 (접기 가능) | 기본 접힘, 아이콘만 |
| 대시보드 KPI | 4열 | 2열 |
| 셀 편집 트리거 | hover → 인라인 편집 | 탭 → 편집 시트 |

원본은 항목명 옆 연필 아이콘이 hover로 나타나는데 터치에서는 동작하지 않는다.
**hover와 탭을 둘 다 지원**하도록 구현한다 (데스크톱은 hover, 터치는 롱프레스/탭).

### 3.6 오프라인 우선
Drive 저장은 네트워크가 필요하다. IndexedDB를 1차 저장소로 두고 Drive는 동기화 대상으로
취급하면, 연결이 끊겨도 입력이 되고 복구되면 자동으로 올라간다.

### 3.7 원본과 **같게** 유지할 것
- 자산 대장의 월 × 항목 그리드 구조 (이게 이 서비스의 정체성)
- 2단계 카테고리 + 이름 수정 + 숨김/복원
- 셀 메모와 메모 표시자
- 월별 노트 (작성완료 배지 포함)
- 금액 마스킹 토글 (블로그·화면 공유 때 유용)
- CSV 내보내기/가져오기
- 대출 셀의 금액 + 금리 2단 표기

## 4. 데이터 모델 (1차 범위)

```jsonc
{
  "version": 1,
  "settings": {
    "baseCurrency": "KRW",
    "maskAmounts": false,
    "comparisonBasis": "MoM"          // MoM | YoY
  },
  "categories": [
    { "id": "c1", "kind": "ASSET", "name": "현금성 자산", "color": "emerald", "order": 1 },
    { "id": "c9", "kind": "DEBT",  "name": "담보대출",    "color": "amber",   "order": 9 }
  ],
  "items": [
    { "id": "i1", "categoryId": "c1", "name": "주택청약저축",
      "currency": "KRW", "hidden": false, "order": 1 },
    { "id": "i4", "categoryId": "c2", "name": "미래에셋 달러 CMA",
      "currency": "USD", "hidden": false, "order": 1 },
    { "id": "i7", "categoryId": "c9", "name": "주택담보대출",
      "currency": "KRW", "hidden": false, "order": 1, "isLoan": true }
  ],
  "snapshots": [
    // 대장의 셀 하나 = 이 레코드 하나. amount는 항목의 원통화 그대로.
    { "itemId": "i1", "ym": "2026-07", "amount": 12000000, "memo": null },
    { "itemId": "i4", "ym": "2026-07", "amount": 12340.55, "memo": null },
    { "itemId": "i7", "ym": "2026-07", "amount": -230000000, "rate": 3.45,
      "memo": "광주은행 금리 인상 +0.5%p" }
  ],
  "fxRates": [
    { "ym": "2026-07", "rates": { "USD": 1385.2, "JPY": 9.12 } }   // 1단위당 원화, 월말 기준
  ],
  "notes": [
    { "module": "ASSET", "ym": "2026-07", "status": "DONE",
      "body": "- 부동산 시세차익 업데이트 ; +1.3억원" }
  ],
  "goals": [
    { "scope": "NET_WORTH", "period": "2026", "target": 1000000000 }
  ]
}
```

설계 판단:

- **금리는 별도 이력 테이블로 빼지 않고 스냅샷에 함께 둔다** (`snapshots[].rate`).
  대장 자체가 이미 월별 스냅샷이라 이걸로 충분하고, 화면 구조와 1:1로 맞아 코드가 단순해진다.
  "2026년 3월에 금리가 3.0%였다"가 그 달 셀에 그대로 남는다.
- **부채는 음수로 저장한다.** 합계·구성비 계산에서 분기문이 사라진다. 화면에는 양수로 표시.
- **`ym` 문자열 키**(`"2026-07"`)를 쓴다. 정렬·비교·그룹핑이 전부 문자열 연산으로 끝난다.
- `snapshots`는 값이 있는 셀만 저장한다(sparse). 빈 셀은 레코드 없음 = 미입력.
- **`fxRates.rates`는 "외화 1단위당 원화"** 로 통일한다. JPY는 100엔 단위 관행이 있으나
  혼동을 막기 위해 1엔당으로 저장하고 표시할 때만 100엔 환산한다.

## 5. 단계 계획

| 단계 | 내용 | 산출물 |
|---|---|---|
| **0** | 기존 시트 2종의 구조 파악 → 스키마 확정, 임포터 매핑표 작성 | 매핑 문서 |
| **1** | 앱 셸(사이드바·라우팅·반응형) + Google 로그인 + Drive 읽기/쓰기 | 로그인해서 빈 데이터 저장되는 앱 |
| **2** | 자산 대장 그리드 (카테고리 관리, 셀 편집, 메모, 숨김, 다통화) + 시트 임포트 | **과거 데이터가 들어간 대장** |
| **3** | 대시보드 (KPI, 구성비, 통화별 현황, 부채 상세, 추이 차트) + 월별 노트 | 1차 완성 |
| — | *여기서 멈추고 실제로 써 본다* | |
| 4 | 포트폴리오 + 시세·환율 프록시 (Cloudflare Workers) | |
| 5 | 타임라인, 목표 계산기 | |

가계부는 구현하지 않으므로 원본의 "이체 거래가 자산 대장 잔액과 어긋나면 어떻게 하나"라는
정합성 문제 자체가 사라진다. 자산 대장은 순수하게 **월말 잔액을 직접 적는 장부**로 남는다.

## 6. 시세·환율 연동 설계 (4단계)

브라우저는 CORS 때문에 Yahoo Finance를 직접 부를 수 없다. 중계용 Worker 하나를 둔다.

| 필요 데이터 | Yahoo 심볼 예 |
|---|---|
| 해외 개별주 | `TSLA`, `PLTR` |
| 국내 ETF | `069500.KS` (코스피), `.KQ` (코스닥) |

### 7.1 기존 시트 구조 — **다음 단계 블로커**

스키마를 확정하려면 두 시트가 실제로 어떻게 생겼는지 봐야 한다. 다음 중 편한 방법으로:

- **시트 상단 몇 행 스크린샷** — 헤더 행 + 데이터 3~5행이면 충분. 금액은 가려도 된다.
  구조(어떤 컬럼이 있고 월이 가로인지 세로인지)만 보이면 된다.
- 또는 시트를 CSV로 내보내 내용을 붙여넣기

확인하려는 것:

**전체 자산 시트**
1. 월이 **가로(컬럼)** 인가 **세로(행)** 인가
2. 상위/하위 분류를 어떻게 표현하고 있는가 (컬럼 분리? 들여쓰기? 병합 셀? 색깔?)
3. **외화 자산을 어떻게 적고 있는가** — 원화로 환산해서 적는가, 달러/엔 그대로 적는가,
   아니면 둘 다 적는가. **환율 컬럼이 따로 있는가**
4. 대출 금리를 어디에 적고 있는가
5. 데이터가 언제부터 있는가 (몇 년치인가)

**주식 시트**
6. 한 행이 **보유 종목(현재 잔고)** 인가 **매매 거래 이력**인가
7. 티커/종목코드를 적는 컬럼이 있는가, 아니면 종목명만 있는가
8. 배당 기록이 있는가
