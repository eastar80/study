# Google Cloud 설정 안내

앱이 **내 Google Drive의 파일 하나**를 읽고 쓰려면, 내 이름으로 발급한 열쇠 두 개가 필요하다.

- **클라이언트 ID** — "이 앱이 나(사용자)에게 권한을 요청할 자격이 있다"는 증명
- **API 키** — 파일 선택 창(Google Picker)을 띄우는 데 쓰는 식별자

두 값 모두 브라우저에 그대로 노출되는 **공개 식별자다. 비밀이 아니다.** 비밀번호가 아니므로
저장소에 넣어도 문제없다. 대신 "내 웹사이트 주소에서만 쓸 수 있다"는 제한을 걸어 남이 가져다
쓰지 못하게 막는다. 이 문서의 4-③, 5-② 단계가 그 제한이다.

**비용은 0원이다.** 결제 수단 등록도 필요 없다. 데스크톱 브라우저에서 10분 정도 걸린다.

---

## 1. Google Cloud 프로젝트 만들기

1. https://console.cloud.google.com 접속 (자산관리에 쓸 Google 계정으로 로그인)
2. 상단 왼쪽 프로젝트 선택 드롭다운 → **새 프로젝트**
3. 프로젝트 이름: `my-asset-manager` (아무 이름이나 상관없다)
4. **만들기** → 생성되면 상단 드롭다운에서 그 프로젝트가 선택되어 있는지 확인

> 이후 모든 단계에서 **상단에 이 프로젝트가 선택되어 있어야 한다.** 엉뚱한 프로젝트에 설정하는
> 것이 가장 흔한 실수다.

---

## 2. API 3개 켜기

좌측 메뉴 **API 및 서비스 → 라이브러리** 에서 아래 3개를 검색해 각각 **사용** 을 누른다.

| API | 용도 |
|---|---|
| **Google Drive API** | 데이터 파일(`data.json`) 읽기/쓰기 |
| **Google Sheets API** | 기존 시트의 값과 서식 읽기 |
| **Google Picker API** | "내 Drive에서 시트 고르기" 창 |

3개를 다 켰는지 **API 및 서비스 → 사용 설정된 API** 에서 확인한다. 하나라도 빠지면
해당 기능만 조용히 실패한다.

---

## 3. 동의 화면 구성

내가 내 앱에 권한을 줄 때 뜨는 화면을 설정한다.

좌측 메뉴에서 **API 및 서비스 → OAuth 동의 화면** 으로 간다.
(콘솔 UI가 개편되어 **Google Auth Platform → 브랜딩 / 대상** 으로 보일 수도 있다. 같은 것이다.)

1. User Type(대상): **외부** 선택 → 만들기
   - "내부"는 Google Workspace 조직 계정만 쓸 수 있다. 개인 Gmail이면 반드시 **외부**다.
2. 앱 정보
   - 앱 이름: `내 자산관리` (동의 화면에 뜨는 이름이다)
   - 사용자 지원 이메일: 본인 이메일
   - 개발자 연락처 정보: 본인 이메일
3. 범위(Scope) — **추가하지 않아도 된다.** 앱이 실행 시점에 직접 요청한다.
   굳이 추가하겠다면 `.../auth/drive.file` 하나만 넣는다.
4. **테스트 사용자** → **+ ADD USERS** → **본인 이메일 주소를 추가한다**
   - ⚠️ **이 단계를 빼먹으면 로그인이 거부된다.** 가장 흔한 실패 원인이다.
5. 게시 상태는 **테스트** 그대로 둔다. 나 혼자 쓰므로 앱 심사(게시)를 받을 필요가 없다.

---

## 4. OAuth 클라이언트 ID 발급

**API 및 서비스 → 사용자 인증 정보 → + 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**

① **애플리케이션 유형**: `웹 애플리케이션`

② **이름**: `asset-manager-web` (내부 식별용)

③ **승인된 JavaScript 원본** — 아래 두 개를 **+ URI 추가** 로 넣는다

```
https://eastar80.github.io
http://localhost:5173
```

- 첫 번째가 실제 배포 주소, 두 번째는 개발용이다.
- **경로(`/study/...`)는 쓰지 않는다.** 도메인까지만 넣어야 한다. 경로를 붙이면 거부된다.
- 끝에 슬래시(`/`)를 붙이지 않는다.

④ **승인된 리디렉션 URI** — **비워 둔다.** 팝업 토큰 방식이라 필요 없다.

⑤ **만들기** → 뜨는 창의 **클라이언트 ID** 를 복사해 둔다.
   `123456789012-abcdefg....apps.googleusercontent.com` 형태다.

---

## 5. API 키 발급

**사용자 인증 정보 → + 사용자 인증 정보 만들기 → API 키**

① 생성된 키를 복사해 둔다. `AIza...` 형태다.

② 바로 **키 제한** 을 건다 (생성 창의 "키 제한" 또는 목록에서 키 이름 클릭).

- **애플리케이션 제한사항**: `웹사이트` 선택 → 아래 두 개 추가
  ```
  https://eastar80.github.io/*
  http://localhost:5173/*
  ```
  (여기는 반대로 **끝에 `/*` 를 붙인다.** 4-③의 형식과 다르다 — 헷갈리기 쉬운 부분이다.)
- **API 제한사항**: `키 제한` 선택 → **Google Picker API** 만 체크
- 저장

---

## 6. 두 값을 알려주기

아래 두 줄을 채워서 대화에 붙여주면 앱에 넣는다.

```
CLIENT_ID = ...apps.googleusercontent.com
API_KEY   = AIza...
```

반복하지만 이 두 값은 브라우저에 노출되는 공개 식별자이며, 4-③·5-② 제한 덕분에 내 도메인
밖에서는 쓸 수 없다. Drive 파일에 접근하려면 그 위에 **내가 직접 동의 화면에서 승인**하는 절차가
반드시 필요하므로, 이 값만으로는 누구도 내 데이터에 닿을 수 없다.

---

## 7. 처음 로그인할 때 보게 되는 것

앱에서 로그인을 누르면 이런 순서로 진행된다.

1. **"Google에서 확인하지 않은 앱"** 경고 화면
   → **고급** → **(앱 이름)(으)로 이동** 클릭.
   테스트 모드의 개인 앱에서는 정상적으로 뜨는 화면이다. 심사를 받지 않았다는 뜻일 뿐이다.
2. 권한 요청 화면에 **"Google Drive의 특정 파일 보기 및 관리"** 한 줄만 떠야 한다.
   - Drive 전체, Gmail, 연락처 같은 항목이 뜨면 **취소하고 알려주기 바란다.** 설정이 잘못된 것이다.
3. 허용 → 앱으로 돌아온다.

권한은 언제든 https://myaccount.google.com/permissions 에서 철회할 수 있다.

---

## 8. 이 앱이 접근할 수 있는 범위

요청하는 권한은 `drive.file` **하나뿐이다.** 이 범위의 정의는 다음과 같다.

> 앱이 **직접 만든 파일**, 그리고 **사용자가 파일 선택 창에서 직접 고른 파일** 에만 접근 가능

따라서:

| | 접근 가능 여부 |
|---|---|
| 앱이 만든 `/Asset Manager/data.json` | ✅ (앱이 만들었으므로) |
| 내가 Picker에서 직접 고른 자산·주식 시트 | ✅ (내가 골랐으므로) |
| Drive의 다른 문서·사진·폴더 | ❌ 목록조차 볼 수 없다 |
| Gmail, 연락처, 캘린더 | ❌ 범위 밖 |

Drive 전체를 훑는 `drive.readonly` 나 `drive` 범위는 요청하지 않는다.

## 문제가 생기면

| 증상 | 원인 |
|---|---|
| `Error 403: access_denied` | 3-④ 테스트 사용자에 본인 계정을 추가하지 않았다 |
| `Error 400: redirect_uri_mismatch` / `origin_mismatch` | 4-③ 승인된 원본이 틀렸다. 경로·슬래시 확인 |
| Picker 창이 안 뜨고 콘솔에 API 키 오류 | 2단계에서 Picker API를 켜지 않았거나 5-② 제한이 틀렸다 |
| 시트를 골랐는데 읽지 못함 | 2단계에서 Sheets API를 켜지 않았다 |
| 설정 직후 여전히 안 됨 | 콘솔 변경이 반영되기까지 몇 분 걸린다. 시크릿 창에서 재시도 |
